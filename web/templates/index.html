한 번에 계획을 만들려면 아래 네 가지를 포함해 주세요.

  • 리소스 이름과 API 무엇: 만들 Custom Resource의 이름과 주소입니다.
    용도: CRD 이름과 kubectl API 경로를 결정합니다.
    예: WebApp, apps.sample.io/v1alpha1
  • 입력값과 타입 무엇: 사용자가 spec에 입력할 값입니다.
    용도: Go 타입과 CRD 검증 Schema를 생성합니다.
    예: image:string, replicas:int32
  • 관리 대상과 동작 무엇: Controller가 다룰 Kubernetes 리소스와 행동입니다.
    용도: Reconcile 코드와 최소 RBAC 권한을 결정합니다.
    예: Deployment 생성·변경·복구
  • 표시할 status와 삭제 방식 무엇: 사용자에게 보여줄 현재 상태와 삭제 시 처리 방법입니다.
    용도: status 갱신과 retain·함께 삭제 정책을 생성합니다.
    예: phase:string, 삭제 시 함께 정리
처음이라면 이렇게 이해하세요

spec은 사용자가 원하는 값을 입력하는 곳이고, status는 Controller가 확인한 실제 결과를 기록하는 곳입니다.

  • image:string → image: nginx:latest처럼 글자를 저장합니다.
  • replicas:int32 → replicas: 3처럼 정수를 저장합니다.
  • enabled:bool → enabled: true처럼 참·거짓을 저장합니다.
  • phase:string → Controller가 phase: Ready처럼 현재 상태를 기록합니다.
